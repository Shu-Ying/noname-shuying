# 梦三模式首次安装分包设计

梦三模式首次安装目前会逐个下载模块清单文件。当前仓库按发布清单规则筛出的梦三模块有 846 个文件，约 143.5 MiB。分包的目标是减少首次安装的网络请求，在手机端控制单次解包的数据量，并保留逐文件校验和安装恢复能力。

## 方案选择

- 逐文件下载适合日常差量更新和少量补缺，继续沿用现有流程。
- 单个 ZIP 请求最少。现有客户端会在内存中拼接完整响应，单个 ZIP 需要持有整个模块的压缩数据。
- 首次安装使用多个有大小上限的独立 ZIP。每次只处理一包，下载失败时可以单独重试。首版覆盖梦三，常规武将和天书乱斗等实测后再决定。

## 发布与安装

GitHub 和 Gitea 的现有发布工作流使用各自同一发布标签的梦三清单生成分包，将分包与完整离线安装包一起上传为 Release 附件。客户端继续使用选定的源和渠道，先获得同一标签的模块清单，再查询该标签的 Release。首次安装每次下载和解开一包，每个文件按清单验证大小和 SHA-256 后写入现有暂存区。全部文件备齐后，现有安装流程再次验证暂存文件并负责替换、回滚和提交安装记录。

旧标签无 ZIP、附件暂不可用、解包失败或内容校验失败时，从同源同标签逐文件补齐。本次已校验并写入暂存区的文件可以继续用。暂存写入失败走现有安装失败处理。退出游戏后，安装按现有方式重新发起，部分下载进度只用于当前操作。已安装的模块更新、查漏补缺、卸载和旧安装迁移沿用现有行为。

## 启用条件

同一部手机、同一版本和同一下载源下，对比两种方式的请求数、总耗时和内存峰值。验证两个源的附件在游戏内均可下载，且 ZIP 不可用时均可从同源回退。手机实测确认有收益后再默认启用。具体分包上限由实测确定。
